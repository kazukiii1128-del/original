# デイリーレポート設計書

**Date:** 2026-04-14  
**Trigger:** ユーザーが「デイリーレポート」と入力

---

## 概要

毎朝ユーザーが「デイリーレポート」とキーワードを入力し、手入力情報を添えると、ClaudeがAPIとDataKeeperからデータを自動取得・統合してチャット上にレポートを出力する。

---

## トリガーフォーマット

```
デイリーレポート
楽天広告: ROAS 3.2, 消化 ¥12,000
在庫: なし  （または問題内容を記載）
アカウント: なし  （または問題内容を記載）
クレーム: なし  （または件数・内容を記載）
今日: ①〇〇 ②〇〇 ③〇〇
```

- 各項目は省略可・「なし」でも空白でもOK
- 楽天広告のみユーザー手入力（DataKeeper未収録）
- 「今日やること3つ」はユーザーが決める

---

## データソース

| セクション | ソース | 取得方法 |
|-----------|--------|---------|
| 楽天 売上・注文数 | Rakuten RMS API | `tools/rakuten_daily_report.py` を実行 |
| Amazon 売上・注文数 | DataKeeper `amazon_sales_daily.json` | ファイル直接読み込み |
| Amazon PPC効率 | DataKeeper `amazon_ads_daily.json` | ファイル直接読み込み |
| 楽天PPC効率 | ユーザー手入力 | チャット入力をパース |
| 在庫・アカウント・クレーム | ユーザー手入力 | チャット入力をパース |
| 今日やること3つ | ユーザー手入力 | チャット入力をパース |

## 実装スコープ

### 新規作成
- `tools/marketplace_daily_report.py` — データ取得・集計ロジック
- `workflows/marketplace_daily_report.md` — Claudeが参照するワークフロー定義

### 既存ツール活用
- `rakuten_daily_report.py` の fetch_yesterday() ロジックを流用（または直接import）
- DataKeeper読み込みは `amazon_daily_report.py` と同様のパターン

### スキル登録
- `デイリーレポート` と入力されたらこのワークフローを呼び出すスキルを登録

---

## エラーハンドリング

- RMS APIが取得できない場合：「楽天データ取得失敗」と表示、他セクションは継続
- DataKeeperファイルが存在しない場合：「Amazonデータなし（DataKeeper未更新）」と表示
- ユーザー入力が空の項目：「なし」として扱う

---

## 制約

- 出力はチャット上のみ（Teams投稿なし）
- 楽天は現在1ショップ（littlefingerusa）のみ対応
- Amazon為替換算はUSD/JPYレートを別途取得するか固定レートを使用
